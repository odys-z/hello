# docx4j facts demo

Shows JAXB in docx4j and a "facts first" walker for building a content tree.

## Run

```bash
mvn package
java -jar target/docx4j-facts-demo-0.1.jar samples/tricky.docx
```

Needs JDK 17+ and Maven Central access. `samples/tricky.docx` is generated by
`python3 gen_sample.py samples/tricky.docx` (python-docx) and contains the cases
style-name-only parsers get wrong:

| Paragraph | Why it's tricky | Expected level |
|---|---|---|
| Annual Report | `Title` style, no outline level | 0 |
| 第一章 总则 | custom style `章标题`, `basedOn` Heading 1 | 1 (inherited) |
| 1.1 Scope | plain `Heading 2` | 2 |
| Direct outline level… | `Normal` style + `w:outlineLvl` on the paragraph | 2 |
| Clause 7… | custom style `Clause` with its own `outlineLvl=2` | 3 |
| First/Second bullet | `List Number`, numbering via style | body, `num` = 1. / 2. |
| table | `gridSpan` + `vMerge` | body, `tableKind: layout` |
| 第二章… | Heading 1 wrapped in a content control (`w:sdt`) | 1 |

## Output sections

1. **JAXB round trip** - builds a `<w:p>` from Java objects, marshals it to XML, unmarshals it back.
2. **Package parts** - every zip part; `JAXB` = parsed into typed objects, `binary` = images, embeddings, etc.
3. **Facts** - per block: source path, style id/name, outline level by docx4j's
   `PropertyResolver` and by an explicit `basedOn` walk, numbering label.
4. **Tree** - stack-built heading tree as JSON, each node carrying `src` back to the source.

## Notes

- `src` like `body/9/sdt/0` = 9th body child, inside a content control, first child. That's the
  stable ID your tree UI and template rules can point at.
- `Emulator.getNumber` is stateful (counters advance per call): call it once per paragraph, in order.
- If `outline(resolver=…)` and `outline(manual=…)` ever differ on your files, the manual walk
  shows exactly which rule produced the value - that's where a template plugin would hook in.
